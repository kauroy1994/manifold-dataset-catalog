## Current repository practice

The repository owner reviews catalog corrections against the primary publications. Changes identify their source, date, reason, and affected asset. Counts remain marked as publication-reported until a separate file-level audit exists. Source datasets stay upstream; no contributor may upload restricted data, credentials, worker images, or unverified experimental results as authoritative facts.

Existing illustrative graph objects must retain their non-empirical status. A website build or passing repository check is not permission to label a process assertion as verified. The catalog may document uncertainty or suspend a questionable link without rewriting original data.

## Proposed funded-resource governance

| Future stage | Proposed review boundary | Required documentation |
|:--|:--|:--|
| Source admission | Rights, acquisition context, identity and privacy | Source manifest, access conditions, limitations |
| Enhancement | Evidence linkage, derivation and assertion status | Inputs, software/model versions, uncertainty and review history |
| Validation | Structural, process, evidence and domain assessment | Test outcomes, unresolved cases and adjudication |
| Release | Authorized approval and permitted access | Versioned datasets, benchmark partitions and release manifest |
| Correction/retirement | Integrity incidents, disputes, rights changes | Correction record, rollback/deprecation notice and retained lineage where lawful |

These are proposed policies for the enhanced resource, not controls implemented by this planning website. No operational archival steward, retention contract, incident-response service level, or external adoption partner is claimed as secured here.

## Authority and independence

The proposed consortium assigns scientific integration to Roy, manufacturing validation to Harik, semantic interoperability to Gaur, graph-learning evaluation to Parthasarathy, and provenance/security to Mittal. Actual release approvers, escalation paths and institutional responsibilities must be agreed before operational data releases.

## Availability limits

GitHub hosts this catalog, code and documentation when the owner publishes it. It is not a promised long-term archive for the original data or future enhanced datasets. Preservation, persistent identifiers and any restricted-data hosting require separately confirmed arrangements.
